# Security Policy

Never commit credentials, API keys, tokens, private customer data, or production dumps.

Security-sensitive changes should use least privilege, explicit trust boundaries, input validation,
safe defaults, dependency review, and negative-path tests. High-impact authentication, authorization,
data-retention, destructive migration, cryptography, secret-management, or external-publication changes
should receive independent review.

Report suspected vulnerabilities privately to the repository owner rather than opening a public issue.
