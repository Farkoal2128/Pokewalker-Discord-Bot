# Documentation Map

- `requirements/` — what the system must do.
- `features/` — canonical implementation plans and progress.
- `decisions/` — architecture decision records.
- `verification/` — evidence that work was actually checked.
- `research/` — time-bounded technical/product research.
- `templates/` — reusable work orders and engineering records.
- `provenance/` — where reusable workflow conventions came from.
- `multi-agent-workflow.md` — five-agent coordination, ownership, TDD, testing, and documentation flow.

Keep intended behavior, observed implementation, executed verification, and external/human approval distinct.
