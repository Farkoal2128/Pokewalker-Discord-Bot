# M1.9 — Unacknowledged terminal results: `/walker` recovery screen

**Tier:** seam (interaction responses; persisted state)

**Goal.** Make every committed outcome reach the player even when the Discord edit after
commit failed, the screen was dismissed, or the process restarted.

- Terminal transitions (`caught`, `fled`, `ran`; M1.7/M1.8) leave `acknowledged_at NULL`.
- `/walker` entry and the `home` handler (M1.6) first query the profile's terminal encounters
  with `acknowledged_at IS NULL`, oldest `resolved_at` first; if one exists, render
  `render_terminal` for it instead of home: for `caught`, the Pokémon (from `pokemon` by
  `source_encounter_id`) and the rewards (from the `resource_ledger` lines of the catch
  receipt), so the screen is rebuilt from durable state, never from a session cache; for
  `fled`/`ran`, the species and outcome. The only button is `Done` (`ack`).
- `ack` handler: writer job sets `acknowledged_at = now` where NULL (idempotent); then shows
  the next unacknowledged result, else home (with its `Open encounter` prompt when the queue
  is non-empty).
- The `Done` buttons on M1.8's result screens dispatch `ack` too, so a normal flow
  acknowledges immediately and a fresh session never re-shows a seen result.
