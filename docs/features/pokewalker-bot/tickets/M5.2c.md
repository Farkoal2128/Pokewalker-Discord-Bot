**Goal.** New under `deploy/`:

- `pokewalker-backup.service`/`.timer`: `OnCalendar=hourly`, `Persistent=true`,
  `RandomizedDelaySec`, `UMask=0077`, `EnvironmentFile=/etc/pokewalker/backup.env`,
  `StateDirectory=pokewalker-backup`, `OnFailure=pokewalker-backup-failed.service`.
- `backup.sh` (env keys: M5.2d `backup.env.example`; no `BACKUP_MONITOR_URL` → refuse to
  run) holds `flock $STATE_DIRECTORY/lock` for the whole run (timer and deploy runs never
  overlap); three stages in order:
  1. **snapshot**: `sqlite3 -readonly … .backup` to a unique `.partial`;
     `integrity_check` + `foreign_key_check`; copy the marker log to a `.partial` beside
     it; rename both. Any failure, **including a missing or uncopyable marker log**
     (lost recovery metadata, no D28 restore point), deletes both partials; an empty log
     (fresh install) is copied like any other.
  2. **upload**, only after 1: `restic backup --tag pokewalker` both files.
  3. **prune**, always (even after 1 or 2 failed): `prune.sh` (M5.2b).
  **Exit = first failed stage**: 1 snapshot (dominates later failures), else 2 upload,
  else 3 prune, else 0; so 2 or 3 imply a verified local snapshot from this run. Each
  failed stage logs `backup: <stage> failed`; the dominant word goes to
  `$STATE_DIRECTORY/failed-stage`. On 0: write `last-success`; `curl` the monitor (10 s
  timeout, no body).
- `backup_alert.sh` (`OnFailure` unit): pings `$BACKUP_MONITOR_URL/fail` with the
  `failed-stage` word (absent → `unknown`), nothing else; a missing success ping alerts
  after the monitor's grace (1 h period, 2 h grace).
- `contracts/ops-runtime.md` (C6): paths incl. M5.2a's handoff, credentials; exit codes
  bot 0/75, deploy 10/20/30/40/50, backup 0/1/2/3 with this precedence, prune 0/1;
  marker-copy, retention and monitor invariants; secrets never in logs or arguments.
