# M4.1a — Write-ahead marker log: append, void, fold, first-use creation

**Tier:** seam (persisted state outside the DB; privacy boundary). Split from M4.1
(review-9 #2) and again into log (this row) and deletion service M4.1b (review-11 #1).
Stdlib only, no database; M4.1b and M4.3 consume it.

**Read:** README.md:60 (D28: a minimal marker appended to a log outside the game DB and
synced to disk **before** deleting; startup re-deletes marked profiles; restore uses the
**newest** log); owner decision 2026-11-04 (PLAN Round 8: opt-out = deletion plus a
marker that stops tracking; opt-in clears it); review-9 #2, review-10 #1, review-11 #1
and **supervisor ruling (Round 11)**: the log is write-ahead; a job that fails after
appending appends a `void` record; replay folds the log per member in order, ignores
voided markers and applies only the final state, independent of receipts.

**Goal.** `pokewalker/services/marker_log.py`:

- `append_marker(path, kind, guild_id, user_id, now, *, profile_id=None, actor_id=None,
  reason=None) -> marker` and `append_void(path, marker_id, now)`: one JSON line each
  (`{marker_id: uuid4, kind, guild_id, user_id, profile_id, at, actor_id, reason}` /
  `{void: marker_id, at}`), `flush` + `os.fsync`. Kinds `delete`, `opt_out`, `opt_in`,
  `reset`. Both are synchronous, so a task cancellation cannot interrupt a record.
  **Torn-tail repair** (review-12 #1, supervisor ruling Round 12): before writing, if
  the file's last byte is not a newline, truncate it to just after the last newline
  (empty if none), fsync and log the dropped byte count. Such a tail is a record whose
  fsync never finished, so its job never applied it; the next record starts on a
  boundary.
- `create_empty(path)`: exclusive create (an existing file is never truncated), fsync the
  file and, on POSIX, its directory.
- `fold(path) -> {(guild_id, user_id): State}`: collect every voided id, then walk the
  valid markers in log order. `State.delete_ids`: the `profile_id` of every `delete`,
  `reset` and profile-bearing `opt_out` (deletions only accumulate; a later opt-in never
  restores data). `State.opted_out`: `True`/`False` from the **last** valid `opt_out` /
  `opt_in`, `None` without one (last valid participation marker wins). `State.resets`:
  each valid reset (marker_id, profile_id, actor_id, reason, at) for its audit. Only an
  unparseable **final** line (a torn tail not yet repaired) is logged and skipped; an
  unparseable or unknown record before it is corruption, so `fold` raises naming the
  line (startup refuses; restore the newest backup copy).
