**Goal.** New under `deploy/` (M5.2c `backup.sh` calls `prune.sh` every run):

- `prune_select.py` (stdlib): `--now <epoch> --days 28` reads `restic snapshots --json
  --tag pokewalker` on stdin and prints the ids with `time < now − 28 d`; `--local <dir>`
  prints the files in `<dir>` (snapshots, marker-log copies, stale `.partial`s) whose
  mtime is below the same cutoff.
- `prune.sh <backup-dir>`: one `now` for both halves. **Local first**: delete the files
  `prune_select.py --local` lists (local retention never waits for the repository).
  **Then remote**, two retryable steps (restic forgets snapshots and removes their data
  separately, review-11 #3): `restic snapshots --json --tag pokewalker | prune_select.py`
  and `restic forget <ids>` when any id is listed (explicit ids: independent of the
  latest snapshot and of path grouping; a stale-only repository is emptied); then
  `restic prune` on **every** run, whether or not this run forgot anything. A
  successful `restic prune` is the remote completion criterion, so data left by an
  earlier failed prune is removed by the next run. Both halves are always attempted.
- **Cross-row contract (C6, written by M5.2c):** `prune.sh` exits 0 only when local
  deletion, any forget and the prune all succeed, else 1, naming each failed step
  (`prune: local|forget|prune failed`) on stderr; no secrets in output. M5.2c maps any
  nonzero status to its stage `prune`. Externals are called by name (tests shim `PATH`).
