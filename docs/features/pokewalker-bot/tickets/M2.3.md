- `pokewalker/services/powerup.py`
  - `balances(conn, profile_id) -> {stardust, candy: {family_id: n}}` (read helper for
    screens; every change still flows through `resource_ledger`).
  - `quote(conn, profile_id, pokemon_uid, content, multipliers)` → `{level_x2,
    cp_before, cp_after, candy_cost, stardust_cost, candy_have, stardust_have, family_id,
    at_cap, affordable}`; band = the one with `min ≤ level_x2 < max_exclusive`;
    `level_x2 >= 80` → `at_cap`, no costs.
  - `power_up(conn, session, pokemon_uid, expected_revision, content, multipliers)` under
    `with_receipt(f"powerup:{pokemon_uid}:{expected_revision}", "powerup", …,
    profile_id=…)` (M2.2a). Inside:
    owner = session profile, not excluded, `state='owned'`, revision equal, not at cap,
    balances ≥ costs — any failure returns the persisted state (`stale|at_cap|insufficient|
    excluded`) and writes nothing. Success: `level_x2+1`, `revision+1`, `candy −cost`,
    `stardust −cost`, ledger lines reason `powerup` (negative deltas). One half-level per
    confirmation; IVs, shiny, gender untouched.

  Confirm disabled when `at_cap` or not affordable; Back), `power_up_confirm` → details
