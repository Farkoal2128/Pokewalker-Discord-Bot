**Goal.** Handlers registered with the M1.6 router, renders in `screens.py`:

- `open_encounter`: select the **oldest unresolved** encounter, `state IN ('queued',
  'revealed')` ordered by `created_at` → writer job: if `queued`, set `state='revealed'` and
  upsert `pokedex(seen_at)` for the species (regional forms count toward the species, D15);
  if already `revealed`, change nothing (reopen after Later, dismissal or restart shows the
  same frozen identity and rolls). ❗ handling lives in M1.6, not here. Render the catch
  screen: name, form, gender sign, shiny badge + "Shiny" text, CP, types, tier word, sprite as
  embed image (exact form/gender/shiny or none), bag counts, selected ball/berry, buttons
  `Ball`, `Berry`, `Throw`, `Later`, `Run` (`Throw` disabled when no balls; M1.8 implements
  it). The screen carries the encounter's current `revision` in its session.
- `select_ball` / `select_berry`: update `sessions.selection` only; no spend.
- `later`: back to home; encounter unchanged (`revealed`, same rolls).
- `run`: shiny → second confirmation naming the Pokémon; confirmed → writer job under
  `with_receipt(key=f"run:{encounter_id}:{expected_revision}")` that first checks, inside
  the transaction: owner = session profile; `restrictions.excluded` is false; `state IN
  ('queued','revealed')`; `encounters.revision == expected_revision`. Any failed check returns
  the **persisted current state** (for a terminal encounter: the caught/fled/ran result and,
  when caught, the Pokémon) without writing. On success: `state='ran'`, `resolved_at`,
  revision bump; queue shrinks; Pokédex untouched. Legendary/Mythical have no special Run
  rule (D47: they hold the slot *until* caught or run from).
- `screens.py`: `render_catch(state)`, `render_run_confirm(state)`, `render_terminal(state)`
  (used when another action already resolved the encounter); text carries every fact the
  image shows (D49).
