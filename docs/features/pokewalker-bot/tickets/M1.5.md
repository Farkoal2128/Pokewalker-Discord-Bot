**Goal.**

- `pokewalker/bot/messages.py`: `on_message` → return early for bots/webhooks, DMs, guilds
  without config, channels with `count_steps=0`, non-enrolled, paused or excluded members
  (paused: record `step_events.reason='paused'` with discarded words for `/walker-mod
  status`; excluded: nothing). Compute `eligible_words` in memory; never store or log content.
  Hand `(profile, words, message.created_at, message_id, channel_id)` to the job below;
  after commit (never inside it) call M1.4b's `reconcile_reaction` for the encounter it
  names, if any.
- `pokewalker/services/stepping.py`
  - `credit_message(conn, …)` — one writer job:
    1. `INSERT OR IGNORE step_events(message_id)`; if ignored, return (processed once).
    2. Build `history` from SQL (accepted words in the previous 3,600 s / 60 s by
       `created_at`, last credited time, digest cache from an in-process LRU per profile).
    3. `domain.steps.accept_message` → store counts, `awarded_c`, `reason`.
    4. `advance_meter(current_c, awarded_c, threshold_c, frozen) -> (new_c, triggers)`;
       frozen meters add nothing (D21, for M3.1).
    5. Encounter meter: if `queue_size < 3` (M1.4: queued + revealed), add
       `awarded_c`; while ≥ 10,000 and queue < 3: subtract, `generate` and insert an encounter
       (route, lure state, rng, frozen identity, `content_version`); keep the remainder. Full
       queue → meter unchanged, no debt (D5).
    6. Companion meter: add `awarded_c` **only if `profiles.companion_uid` is not NULL**;
       otherwise unchanged, keeping partial progress (D30). M2.4 consumes it and tests which
       family gets the Candy after a swap.
    7. If the queue went from 0 to ≥ 1 in this job (D3): insert `reactions(encounter_id,
       channel_id, message_id, desired='add', actual='none')` and return that encounter id.
       The Discord call itself, its crash-safety and the removal rule are M1.4b.
