# M4.1c — Startup: marker-log initialization record and replay

**Tier:** seam (persisted state; privacy boundary; process lifecycle). Split from M4.1b

**Read:** README.md:60 (D28: startup re-deletes marked profiles; restore uses the

`marker_log_init`); review-11 #2 (replay must not block startup forever), #5, review-12 #3
and **supervisor ruling (Round 12)**: on every startup, a present log with no init row
gets the row (idempotent); refuse only when the row exists and the log is missing.
Code: client.py:74-85 (`_setup`, before `admitting`); db/__init__.py:105-141.

**Goal.** `pokewalker/services/deletion.py` adds `replay_markers(writer, path)`, called
in `_setup` before `admitting` on **every** start:

1. **Initialization record:**
   - log present and no `marker_log_init` row → insert it. This covers a crash between
     create and record, and an older DB restored beside a newer log.
   - log absent and no row → `create_empty`, then insert the row (first use).
   - log absent but row present → refuse to start ("marker log missing: restore the
     newest copy, D28").
   - both present → nothing.
2. **Replay:** `fold` (a `fold` corruption error refuses startup, M4.1a). Per member, one
   job applies deletions + participation and one job per reset audit. An audit refused
   by a constraint (`IntegrityError`) is logged and skipped; its deletion still
   applies, so startup continues. Receipts never decide whether state applies.

Wiring: one call in `client.py` `_setup`.
