**Goal.**

**In `pokewalker/bot/trade.py`, add `command(bot)`:**
- `@app_commands.command(name='trade', description='Trade a Pokémon with a member of this server')`, `@app_commands.guild_only()`.
- Optional parameter `member: discord.Member`, with a describe.
- Defer ephemerally. If there is no guild: "Use /trade in a server."

Then one writer job applies these checks in order:
1. Opted out → "Run /walker-account opt-in first".
2. No profile → "Open /walker to enroll before trading."
3. Excluded → `EXCLUDED`.
4. Member is a bot → "You can't trade with a bot."
5. Member omitted → `trading.current`, else "Use /trade member to start a trade."
6. Otherwise `trading.open_trade`, whose refusals map to text:
   - `self`: "You can't trade with yourself."
   - `partner_not_enrolled`: "They haven't started walking in this server."
   - `partner_unavailable`: "They can't trade right now."
   - `busy` / `partner_busy`: names the other trade's member and its expiry.

On success, insert a Walker session using the raid.py:30-36 pattern (revision 0, `expires_at=now+900`, selection `{trade_id, trade_revision}`) and render `render_trade(view(...))`. Edit the response with `AllowedMentions.none()`.

**In `pokewalker/bot/client.py`:** import the command and `self.tree.add_command(trade_command(self))` after raid (:93). Nothing else changes; `/walker` gets no option.

**Help text:** append the owner-approved G-A line to `content/help.md` and update the pinned hash at tests/test_readme.py:19. This is docs, not production. If the line is not approved, leave `help.md` unchanged and flag it at G-F.
