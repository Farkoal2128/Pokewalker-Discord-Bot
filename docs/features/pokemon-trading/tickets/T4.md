**Goal.** In `services/trading.py`, `confirm(conn, session, trade_id, seen_revision, now, content)` runs in one job:

1. **Owner check:** a non-participant or unjoined caller gets `stale`.
2. **Trade state:** `completed` → `{status: 'completed', trade_id}` (double-accept); `ended`; `expired`; seen revision differs → `changed`.
3. **Both sides ready:** unjoined or offerless side → `incomplete`.
4. **Cap and exclusion:** `capped` (with `seconds_left`), `partner_capped`, or `partner_unavailable` (partner excluded; clears my confirmation).
5. **Confirm:** set my `confirmed_revision=revision` and run activity (`expires_at=MAX(expires_at,:now+900)`, OD9). Partner's differs → `waiting` (commit).
6. **Re-check offers:** each side's Pokémon must still pass `storage.detail(owner, uid)` at the pinned revision with `tradable_reason` None (identity via `storage.identify(content, …)`). If a side fails, clear that offer and both confirmations, bump the revision, and return `{status: 'offer_invalid', side, reason}`; this commits the cleanup only.
7. **Write:**
   1. `UPDATE profiles SET last_trade_at=:now WHERE profile_id IN (:a,:b) AND (last_trade_at IS NULL OR last_trade_at<=:now-86400)`. A rowcount other than 2 raises (no savepoint).
   2. `UPDATE pokemon SET profile_id=:to, revision=revision+1 WHERE pokemon_uid=:uid AND profile_id=:from AND revision=:pin AND state='owned' AND favorite=0 AND gym_deployment_id IS NULL`, for each side. A rowcount other than 1 raises.
   3. `UPDATE encounters SET acknowledged_at=:now WHERE encounter_id=:source_encounter_id AND acknowledged_at IS NULL`, for each side (no-op when NULL).
   4. Mark the trade `completed` with `ended_at`, bump its revision (the trigger closes the sides), and return `{status: 'completed', trade_id}`.

   A raise rolls back the whole job (unreachable after step 4; trigger is a second backstop). No receipt; no Candy, Stardust or items move.
