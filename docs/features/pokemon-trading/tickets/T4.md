**Tier:** seam (trading; persisted state; abuse controls)

**Read:** PLAN §4.1 P3–P5, P7, P9, P10, P14; T3; db/__init__.py:110-116; gyms.py:215-221 (savepoint refusal); bot/storage.py:207-216 (companion change does not bump revision); deletion.py:125-131; tests/test_deletion.py:256-284.

**Goal.** In `services/trading.py`:

**`confirm(conn, session, trade_id, seen_revision, now, content)`** runs in one job:
1. Owner check; a non-participant or unjoined caller gets `stale`.
2. State `completed` → return `{status: 'completed', trade_id}` (double-accept). Not open → `ended`; due → `expired`; seen revision differs → `changed`.
3. Either side unjoined or without an offer → `incomplete`.
4. Caller capped → `capped` with `seconds_left`. Partner capped → `partner_capped`. Partner excluded → `partner_unavailable` (clear my confirmation).
5. Set my `confirmed_revision=revision`. If the partner's differs → `waiting` (commit).
6. **Execute.** Each side's Pokémon must exist under its owner (`storage.detail`) at its pinned revision, with `tradable_reason` None (identity via `storage.identify(content, …)`). If a side fails: clear that offer and both confirmations, bump the revision, return `{status: 'offer_invalid', side, reason}` (commits the cleanup only).
7. `SAVEPOINT trade_execute`.
   - Run `UPDATE profiles SET last_trade_at=:now WHERE profile_id IN (:a,:b) AND (last_trade_at IS NULL OR last_trade_at<=:now-86400)`. Anything other than 2 rows → `ROLLBACK TO`/`RELEASE`, clear both confirmations, return `capped`/`partner_capped`.
   - Then swap each Pokémon with `UPDATE pokemon SET profile_id=:to, revision=revision+1 WHERE pokemon_uid=:uid AND profile_id=:from AND revision=:pin AND state='owned' AND favorite=0 AND gym_deployment_id IS NULL`. A rowcount other than 1 raises (whole job rolls back; trigger backstop).
   - Set the trade to `completed` with `ended_at`, bump the revision (the trigger closes the sides), and `RELEASE`.
   - Return `{status: 'completed', trade_id}`. There is no receipt (P9), and no Candy, Stardust or items move.

`content` is used here for identity and by T5's Pokédex step.
