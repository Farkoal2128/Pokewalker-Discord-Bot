# T3 — confirm and atomic swap; view snapshot; deletion cases

**Tier:** seam (trading; persisted state)

**Read:** PLAN §4.1 P3–P5, P7–P10, P14; T2; db/__init__.py:110-116, :158-176; evolution.py:49-94 (receipt-first); bot/storage.py:207-216 (companion change does not bump revision); deletion.py:125-131; tests/test_deletion.py:256-284.

**Goal.** In `pokewalker/services/trading.py`:

**`confirm(conn, session, trade_id, seen_revision, now)`** runs in one job:
1. `session_owner`; a non-participant gets `stale`.
2. Receipt `trade:<trade_id>` exists → its saved result to either participant (double-accept).
3. Not open → `ended`; due → `expired`; seen revision differs → `changed`; empty side → `incomplete`.
4. Set my `confirmed_revision=revision`. If the partner's differs → `waiting` (commit).
5. Execute:
   - Partner excluded → `partner_unavailable`; clear my confirmation.
   - Each side: `storage.detail(owner, uid)` exists at the pinned revision and `tradable_reason` is None.
   - If a side fails: clear that offer and both confirmations, bump the revision, return `{status: 'offer_invalid', side, reason}` (commits the cleanup only).
6. Swap each with `UPDATE pokemon SET profile_id=:to, revision=revision+1 WHERE pokemon_uid=:uid AND profile_id=:from AND revision=:pin AND state='owned' AND favorite=0 AND gym_deployment_id IS NULL`; rowcount ≠ 1 → raise (rollback); trigger backstop.
7. Set the trade to `completed` with `ended_at` and a bumped revision (the trigger closes the sides).
8. `with_receipt(conn, f'trade:{trade_id}', 'trade', ..., profile_id=caller)` → `{status: 'completed', trade_id, uids: [side0, side1]}`: no user/profile IDs, no ledger lines, and no Candy, Stardust, items, Pokédex or milestones (Q2/Q4 defaults).

**`view(conn, session, trade_id, now, content, multipliers)`** (participant-only) returns a detached snapshot: state, revision, expires_at, partner user_id, `my_side`, both offers via `storage.stats` with shiny/Legendary/Mythical/`origin` flags (Q5), both confirmed flags.
